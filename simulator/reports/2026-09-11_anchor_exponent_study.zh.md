# mixmax_wn 打分中宽度因子 (A/L)^α 的 anchor 与指数:理论分析与实验报告

日期:2026-09-07(在线实验 11:17–20:37 UTC),2026-09-08 重写(v2:改用平实的表述;§2 补充推导、实测机制与文献),2026-09-10/11 增加 §7 补充验证。代码:TreeSparseAttention 分支 `shiqihe/region-aware`,提交 a5519ee(anchor 改为可配置参数 `BSA2_WN_ANCHOR` / `TSA_WN_ANCHOR`,默认值 16,默认行为不变)与 54018b8(README 参数表)。在线实验全部在 spark00 的 sglang serve(`--decode-attention-backend bsa_v2`)上运行;离线分析用 23 个真实失败样本的 KV dump。

要回答的问题:mixmax_wn 打分里宽度项的缩放因子是 (16/L)^0.25。这个 16 从哪来?有数学依据吗?这个因子为什么是这个形式?能不能换成 8、32、64、所有块长的 median 或 mean?换了以后 0.25 要变成多少?哪个最好?

## 0. 结论速览

1. **这个因子存在的原因:在 token budget 下选块是一个 knapsack 问题,应当按"每个 token 携带的 attention mass"排序;Quest 的 upper bound 估计的是"块内单个 token 的最大分数",它随块长增长,对变长块有系统性的偏向。** 实测(§2.2):Quest bound c + w 与块的总 attention mass 的 Spearman 相关是 +0.85,但与每 token 的 mass 只有 +0.22;center term c 单独与每 token 的 mass 相关 +0.86。等长 page 下总 mass 与密度排序一致,所以 Quest 不需要归一化;变长块(6–256 token)下两者不一致,bound 型分数必须去掉对块长的依赖。
2. **因子为什么是 (A/L)^α:** center term c 不随块长变化,width term w 随块长增长(随机片段上 w ≈ 17 + 47.6·ln L,在 8–256 token 范围内与 L^0.245 的偏差在 ±10% 内)。用 L^(−α)、α ≈ 0.25 乘 w,就把 w 的期望做成与块长无关。这是对 bound 的偏差校正,不是对 bound 的收紧。增长的来源(§2.4 实测):块内 key 的取值范围随 token 数按 extreme value 规律增长(iid 高斯给出 √(2 ln L)),叠加 RoPE 旋转在中频维度上造成的与位置跨度成正比的扩展(旋转角在 8–256 token 内跨过 1 rad 的维度增长指数最高,0.33)。
3. **A 与 α 是两个独立参数:** (A/L)^α = A^α · L^(−α)。α 是校正的斜率,由 w 的增长指数 β 决定(实测 0.245,范围 0.192–0.279),与 A 无关;A 只通过 λ = A^α 决定 width term 的整体权重。**不存在"换了 A 之后调 α 完全等价"的解**(§2.5 有证明);在一个参考长度 L\* 处近似补偿的公式是 α′ = 0.25·ln(16/L\*)/ln(A′/L\*),A′ ≥ L\* 时无正解。
4. **16 的来源与含义:** 16 是 KV page size(sglang `--page-size 16`、Quest 的 page 粒度、之前所有报告里的 fixed-16 baseline),使 16 token 的块与 Quest 打分完全相同。它没有最优性,但有一个可以量化的位置:λ = 2 时 width term 对排序方差的贡献与 center term 大致相当(同一 prompt 内 std(c)/std(u) 的中位数是 1.77,10%–90% 分位 1.27–2.52);λ 超过约 2.5 后 width term 主导排序,精度开始下降。
5. **实验:** α = 0.25 是 α 轴的最优点(在线 132 步:0.125 → 45,0.25 → 54,0.375 → 51,0.5 → 36)。α = 0.25 时 A ∈ [1, 32](λ 1.0–2.4)在 369 个不重复 step 上与 16 的差异在 ±2 之内(A = 8:184,A = 4:183,A = 16:182,p ≥ 0.87);A = 64 在 strat20 上 −8、在独立的 half2 上 +3,median / mean 在 strat20 上 −6 / −2,即 A 在 1–64 内没有一致影响(§7.4);两个补偿点 (8, 0.1533)、(32, 0.6774) 分别 −6、−18;去掉 width term(ctr-only)−3,而它在离线三项指标上全部最高。
6. **建议:** 保留 16 / 0.25。median / mean 作为 A 没有收益;α 是唯一敏感的参数(§7.4),不要为换 A 去改 α。若将来重选默认值,A = 8 与 16 精度相同;更简单的 ctr-only(box center 打分,与 MoBA / Tactic 的 centroid 打分同一类)值得在更大规模上验证。

## 1. 术语表

| 术语 | 定义 |
|---|---|
| **chunk(块)** | KV cache 中一段连续 token,是稀疏选择的最小单位。本文的块由 region-aware chunker 产生:DOM 区(页面元素列表)按元素切,长度 6–64 token;system prompt 与历史对话区按 parse 树合并,长度 64–256 token。 |
| **envelope(包络)/ bounding box** | 一个块内所有 key 向量按维度取最大值得到向量 M、取最小值得到向量 m。[m, M] 是包含全部 key 的 axis-aligned bounding box。M、m 各 128 维,每个 KV head 各有一对。 |
| **center term(中心项)c** | c = q̄·(M+m)/2,query 与 box 中心的点积。q̄ 是同一 KV head 组内 8 个 query head 的平均向量。 |
| **width term(宽度项)w** | w = Σ_d \|q̄_d\|·(M_d − m_d)/2。它是 query 方向上 box 的半宽:box 内任意一点与 q̄ 的点积最大值等于 c + w。 |
| **upper bound(上界)** | 对块内任意 key k 都有 q̄·k ≤ c + w。Quest 的每块分数就是 c + w。它是一个上界,不是块内真实最大点积;两者之差本文称为 **gap**。 |
| **true max** | 块内 key 与 q̄ 点积的真实最大值 max_i q̄·k_i(对 4 个 KV head 取平均)。 |
| **mixmax_wn 分数 s** | s = c + f(L)·w,f(L) = (A/L)^α,L 是块的 token 数。4 个 KV head 的分数取平均后排序。α = 0 时 f ≡ 1,分数等于 Quest 的 bound(下文记 plain mixmax);f ≡ 0 时只剩 center term(下文记 ctr-only)。 |
| **anchor(参考长度)A** | 因子 f 在 L = A 处等于 1。当前默认 A = 16。 |
| **exponent(指数)α** | 因子随 L 减小的速率。当前默认 0.25。 |
| **width weight λ** | λ = A^α。因为 (A/L)^α = A^α·L^(−α),λ 是 width term 的整体权重。 |
| **u** | 长度归一化后的 width term,u = L^(−0.25)·w。于是 s = c + λ·u。 |
| **admission(准入)** | 按分数从高到低把块加入选中集合,直到累计 token 数达到 budget。system prompt 先保证 25% 预算(sys floor),剩余按全局排序补齐;always-include(开头 4 个 token 与最近 128 个 token)不计入预算。 |

| **attention mass(注意力质量)** | dense 注意力权重(softmax 后,32 个 query head 平均)落在某些 token 上的总和。**mass** 指被准入 token 上的比例;**sysCov** 指 system prompt 区域内被准入的注意力占该区域全部注意力的比例;**mass density(密度)** 指一个块的 attention mass 除以它的 token 数。 |
| **needle** | 离线指标。对每一次打分,参考动作所点击的元素所在块是否被准入(是 = 1,否 = 0),取平均。 |
| **agree / valid / none / error** | 在线指标。teacher-forced 单步复现中,模型输出的元素索引与参考动作一致记 agree;输出合法索引但不一致记 valid;没有输出索引记 none;请求超时或出错记 error。 |
| **paired W/L 与 sign test** | 两个配置在同一 (task, step) 上比较:一方 agree、另一方不 agree 计为该方一次 win。双侧 binomial sign test 给出 p 值;p > 0.05 视为无法区分。 |

## 2. 这个因子在做什么:数学分析与实测机制

### 2.1 Quest 的 bound 与 mixmax_wn 的分数

对一个块的 key 集合 {k_i},Quest [1] 的分数是
$$\text{bound} = \sum_d \max(q_d M_d,\; q_d m_d) = \underbrace{q\cdot\tfrac{M+m}{2}}_{c} + \underbrace{\sum_d |q_d|\,\tfrac{M_d-m_d}{2}}_{w},$$
即 q 在 bounding box 上的 support function:box 内与 q 点积最大的点是 box 的一个角。同样形式的 bound 在 maximum inner product search(MIPS)的树搜索里用于剪枝(ball bound:中心点积 + 半径·‖q‖,Ram & Gray 2012 [6]);用于剪枝时它是 sound 的,因为真实最大值一定不超过它。Quest 把它用作每个 16 token page 的分数并取 top-k。ArkVale [2] 同样用 bounding volume(box 与 sphere)做 page digest 并按 bound 排序。

mixmax_wn 的分数是 s = c + f(L)·w,f(L) = (A/L)^α,默认 A = 16、α = 0.25。mixmax_wn 对一个块的完整打分(与 `bsa_sglang/selection.py` 的 `mixmax_scores_batched` 和 `python/tree_sparse_selector.py` 的 `_score_mixmax` 一致):

$$
s(\text{chunk})=\frac{1}{H_{kv}}\sum_{h=1}^{H_{kv}}\Bigg[\underbrace{\bar q_h\cdot\frac{M_h+m_h}{2}}_{c_h\ (\text{center term})}\;+\;\Big(\frac{A}{L}\Big)^{\alpha}\underbrace{\sum_{d=1}^{D}|\bar q_{h,d}|\,\frac{M_{h,d}-m_{h,d}}{2}}_{w_h\ (\text{width term})}\Bigg],
\qquad \bar q_h=\frac{1}{8}\sum_{g\in\text{group}(h)} q_g
$$

其中 L 是块的 token 数,M_h、m_h 是该块的 key 在 KV head h 上按维度取的最大值和最小值(D = 128 维),q̄_h 是共享 KV head h 的 8 个 query head 的平均,H_kv = 4,默认 A = 16、α = 0.25。独立版实现还乘以常数 1/√D,不影响排序。因为 (A/L)^α = A^α·L^(−α),它等价于 s = mean_h [c_h + λ·L^(−α)·w_h],λ = A^α(默认 λ = 2)。改动前两条打分路径各写死一次 16:

```python
# python/tree_sparse_selector.py:1381 (独立 serve.py 路径)
self._mixmax_wn_factor = (16.0 / lens).pow(self.config.wn_alpha)
# bsa_sglang/selection.py:173 (sglang 路径, mixmax_scores_batched)
factor = (16.0 / chunk_lens.clamp(min=1.0)).pow(wn_alpha)  # [B,C]
```

本次改成可配置的 anchor(`bsa_sglang/selection.py` 新增 `wn_anchor_lengths()`,`backend_v2.py` 读 `BSA2_WN_ANCHOR`,`TreeSparseConfig.wn_anchor` 与 `serve.py` 读 `TSA_WN_ANCHOR`),取值为正数或 `mean` / `median`(按当前 prompt 的全部块长在 GPU 上计算,不含 padding 块,CUDA graph 下可用)。单元测试 `bsa_sglang/test_wn_anchor.py`(5 个用例):默认值与旧实现逐元素一致;固定 anchor 8/32/64 与手算一致;mean / median 排除 padding 后按请求分别计算;§2.5 的恒等式。

### 2.2 为什么等长 page 不需要归一化,变长块需要:budget 下的选择是 knapsack

在 token budget B 下,准入规则是按分数从高到低取块直到累计 token 数达到 B。如果目标是让被准入的 token 承载尽可能多的 attention mass,这是一个 knapsack 问题,贪心解应当按**每 token 的 mass(密度)**排序,而不是按每块的总 mass。

- 等长 page(Quest):所有 page 的 token 数相同,总 mass 与密度只差一个常数,排序一致。bound 随块长增长的性质不影响排序。
- 变长块(本文,6–256 token):总 mass 与密度的排序不同。一个 256 token 的历史块总 mass 可以很高,但每 token 很低;一个 8 token 的 DOM 元素块相反。

我们在 23 个 prompt、4 层、每层若干 decode step 的真实 K/q 上,对每个 (query, 块) 计算了各种分数,并与三个真实量做 Spearman 相关(按 query 平均;`anchor_insight2.py`):

| 分数 | 与总 mass | 与密度(mass / L) | 与 true max |
|---|---|---|---|
| c(center term) | +0.437 | **+0.861** | +0.703 |
| u = L^(−0.25)·w | +0.080 | +0.328 | +0.323 |
| w(原始 width term) | +0.737 | +0.044 | +0.458 |
| c + u(λ = 1,A = 1) | +0.435 | +0.839 | +0.728 |
| c + 2u(λ = 2,A = 16,当前默认) | +0.389 | +0.763 | +0.682 |
| c + 4u(λ = 4) | +0.301 | +0.636 | +0.584 |
| c + w(Quest bound,plain mixmax) | **+0.846** | +0.219 | +0.612 |
| c + w − ln L | +0.845 | +0.319 | +0.691 |
| true max(oracle) | +0.796 | +0.780 | +1.000 |
| true max − ln L(oracle) | +0.270 | +0.843 | +0.670 |

三个结论:
1. Quest 的 bound 是总 mass 的很好的预测量(+0.85),但与密度几乎无关(+0.22)。原因是 bound 和总 mass 都随块长增长(§2.3)。
2. center term 单独就是密度最好的预测量(+0.86),甚至高于 oracle 的 true max(+0.78):块内真实最大点积仍然随块长增长,而密度不随块长变化。
3. width term 的权重 λ 越大,与密度的相关越低(0.861 → 0.839 → 0.763 → 0.636 → 0.219)。这与 §3 的离线 mass 顺序(ctr-only > A = 1 > 4 > 8 > 16)和 §4 的在线结果(λ ≤ 2.4 不可区分,λ ≥ 2.6 下降)一致。

所以 (A/L)^α 因子的作用不是让 bound 更紧,而是把一个"总 mass 型"的分数往"密度型"分数拉:去掉 w 对块长的依赖(§2.3),并用 λ 控制它的权重(§2.5)。

### 2.3 各项随块长的实测变化:因子为什么是这个形式

同一批数据,按块长分组,各量的均值(logit 单位,已乘 1/√128;`anchor_insight2.py`):

| 块长 L | c | w | c + w(bound) | true max | gap = bound − true max | 块内平均 logit | log 密度 |
|---|---|---|---|---|---|---|---|
| 1–8 | −0.51 | 8.33 | 7.82 | 1.01 | 6.81 | −0.61 | −11.04 |
| 9–16 | −0.49 | 12.17 | 11.67 | 1.88 | 9.79 | −0.74 | −10.84 |
| 17–32 | −0.36 | 14.74 | 14.38 | 2.53 | 11.86 | −0.69 | −10.64 |
| 33–64 | −0.38 | 18.10 | 17.71 | 3.15 | 14.56 | −0.75 | −10.59 |
| 65–128 | 0.18 | 20.01 | 20.19 | 3.83 | 16.36 | 0.03 | −10.11 |
| 129–256 | −0.54 | 24.12 | 23.58 | 3.82 | 19.76 | −0.86 | −10.76 |

- center term c、块内平均 logit、log 密度都不随块长变化(c 在 −0.5 附近;65–128 的一组略高,是 system prompt 块)。
- true max 从 1.0 增长到 3.8:块越长,最大值越大,这是 extreme value 的正常规律。
- width term w 从 8.3 增长到 24.1;bound 对 true max 的高估(gap)从 6.8 增长到 19.8 个 logit。以 softmax 计,e^6.8 ≈ 900 倍,e^19.8 ≈ 4×10⁸ 倍——这个 bound 在真实 KV 上远不是紧的,它的数值几乎完全由 w 决定,而 w 主要反映块长。

因此,要得到一个与密度对齐的分数,需要去掉 w 中随块长增长的部分,而 c 不需要处理。w 随块长的增长规律(随机连续片段,150 个片段 × 4 层 × 23 个 prompt,`measure_width.py`):

| L | w 均值 | 相对 L = 16 | (16/L)^0.25 | 校正后 |
|---|---|---|---|---|
| 8 | 116.1 | 0.767 | 1.189 | 0.912 |
| 16 | 151.3 | 1.000 | 1.000 | 1.000 |
| 32 | 185.6 | 1.227 | 0.841 | 1.031 |
| 64 | 219.2 | 1.449 | 0.707 | 1.024 |
| 128 | 250.5 | 1.656 | 0.595 | 0.985 |
| 256 | 281.1 | 1.858 | 0.500 | 0.929 |

相邻区间的局部指数从 0.38(8→16)降到 0.17(128→256);对数拟合 w ≈ 17.1 + 47.6·ln L 在全部六个点上的误差 < 2%。也就是说 w 的增长是对数型的;幂律 L^0.245(最小二乘,按 (dump, layer) 分别拟合的范围是 0.192–0.279)是它在 8–256 这个工作区间内的近似,校正后 w 的比值落在 0.91–1.03。我们把对数形式 f(L) = (0.36 + ln 16)/(0.36 + ln L) 也做了离线评测(`anchor_insight.py`):mass 与幂律相同(B1024 .261 vs .259,B2048 .365 vs .364),只是 needle 略低、sysCov 略高。**因子的具体函数形式不重要,重要的是它的斜率与 w 的实际增长匹配;** 幂律形式只是因为它有一个直观的参数化 (A, α)。

### 2.4 宽度增长的来源:extreme value 与 RoPE(实测)

w 为什么随块长增长、为什么是这个速率?两个来源,都可以在数据上验证。

**(1) extreme value。** 如果块内 key 在每个维度上是独立同分布的,极差 max − min 的期望按 √(2 ln L) 增长。Monte Carlo(2×10⁵ 次,标准正态):

| L | 6 | 8 | 16 | 32 | 64 | 128 | 256 |
|---|---|---|---|---|---|---|---|
| E[max − min] | 2.536 | 2.845 | 3.532 | 4.138 | 4.688 | 5.190 | 5.654 |
| 相邻区间局部指数 | — | 0.401 | 0.312 | 0.228 | 0.180 | 0.147 | 0.124 |

16–256 上的平均指数只有 0.170,比实测的 0.245 低。

**(2) RoPE。** KV cache 里存的是旋转后的 key。第 j 对维度按 θ_j·pos 旋转(θ_j = 10⁶^(−2j/128)),一个跨 L 个位置的块在这对维度上的旋转角跨度是 θ_j·L:θ_j·L ≪ 1 时,这两维的取值范围与 L 成正比;θ_j·L ≫ 1 时已经转过整圈,范围饱和。所以在 8–256 token 范围内,旋转角恰好跨过 1 rad 的中频维度贡献最大的增长。按频带实测(12 个 prompt × 4 层,随机片段,`rope_band_width.py`):

| 维度对 j | θ_j 范围 | 8 | 16 | 32 | 64 | 128 | 256 | 增长指数(8→256) |
|---|---|---|---|---|---|---|---|---|
| 0–7(高频,L = 8 已饱和) | 1.0 – 0.22 | 1.00 | 1.33 | 1.56 | 1.72 | 1.86 | 2.00 | 0.199 |
| 8–15 | 0.18 – 0.039 | 1.00 | 1.39 | 1.90 | 2.45 | 2.87 | 3.12 | **0.328** |
| 16–23 | 0.032 – 0.007 | 1.00 | 1.27 | 1.52 | 1.81 | 2.19 | 2.72 | **0.289** |
| 24–31 | 5.6e−3 – 1.2e−3 | 1.00 | 1.26 | 1.48 | 1.69 | 1.89 | 2.10 | 0.214 |
| 32–39 | 1.0e−3 – 2.2e−4 | 1.00 | 1.27 | 1.50 | 1.72 | 1.92 | 2.11 | 0.216 |
| 40–47 | 1.8e−4 – 3.9e−5 | 1.00 | 1.28 | 1.52 | 1.75 | 1.96 | 2.17 | 0.223 |
| 48–55 | 3.2e−5 – 7.0e−6 | 1.00 | 1.30 | 1.57 | 1.83 | 2.08 | 2.33 | 0.244 |
| 56–63(低频) | 5.6e−6 – 1.2e−6 | 1.00 | 1.32 | 1.62 | 1.91 | 2.19 | 2.47 | 0.260 |
| 全部维度合计 | | 1.00 | 1.30 | 1.58 | 1.86 | 2.11 | 2.36 | **0.248** |

- 已经饱和的高频维度(j = 0–7)只剩 key 内容本身的极值增长,指数 0.20,与 iid 模型一致。
- 旋转角在 8–256 token 内跨过 1 rad 的两个频带(j = 8–23;θ_j·L 在 L = 8 时为 0.25–1.4,L = 256 时为 8–46)指数最高,0.33 与 0.29。
- 低频维度(j ≥ 32,256 token 内旋转不到 0.3 rad)指数 0.21–0.26,略高于 iid,说明这些维度上的 key 内容在一个块内有缓慢的漂移(相邻 token 的 key 不独立)。
- 合计指数 0.248,与 §2.3 的 0.245 一致。

结论:β ≈ 0.25 是这个模型的 key 几何(RoPE base、head 维度、内容统计)的属性,不是 web-agent 数据的属性。换模型或换 RoPE base 应当重新测 β(`measure_width.py`,CPU 上几分钟),然后取 α = β。

### 2.5 A 与 α 的分工;16 的位置;不存在精确补偿

$$(A/L)^{\alpha} = A^{\alpha}\cdot L^{-\alpha} = \lambda\cdot L^{-\alpha},\qquad \lambda = A^{\alpha}.$$

所以 s = c + λ·u,u = L^(−α)·w。α 决定 u 是否与块长无关(§2.3:α = β);A 只通过 λ 决定 u 的权重。固定 α = 0.25 换 A,等于把所有块的 width term 统一乘以 (A′/16)^0.25,center term 不变:

| A′ | 8 | 16 | 32 | 64 | median(L) = 47.6 | mean(L) = 79.3 |
|---|---|---|---|---|---|---|
| λ = A′^0.25 | 1.682 | 2.000 | 2.378 | 2.828 | 2.627 | 2.984 |
| 相对默认值的 width term 倍数 | 0.841 | 1 | 1.189 | 1.414 | 1.314 | 1.492 |

单元测试 `test_fixed_anchor_is_a_global_width_weight` 验证了对任意 query 与 envelope,s₆₄ − s₃₂ = 2^0.25·(s₃₂ − s₁₆)。**"用 median 或 mean 做 A"在固定 α 下只是把 λ 从 2 提高到 2.6 或 3.0,同一个 prompt 内所有块共享同一个 A,没有引入任何自适应。**

**16 的位置。** 16 = page size,使 16 token 的块与 Quest 分数相同,这是它被选中的原因;它对应 λ = 2。λ 的合理范围可以从数据估计:同一 prompt 内各块 center term 的标准差 std(c) 与归一化 width term 的标准差 std(u) 之比(1588 个 query,`anchor_insight.py`):

| | 均值 | 中位数 | 10% 分位 | 90% 分位 |
|---|---|---|---|---|
| std(c) / std(u),全部块 | 1.86 | 1.77 | 1.27 | 2.52 |
| 只看非 system 块 | 1.58 | 1.55 | | |
| 按层:0 / 12 / 24 / 36 | 1.62 / 2.00 / 2.09 / 1.74 | | | |

λ·std(u) 与 std(c) 相等时两项对排序方差的贡献相当;λ = 2 大致就在这个点上。λ 超过 90% 分位的 2.5 之后,在大多数 query 上 width term 主导排序——而 width term 与密度的相关只有 +0.33(§2.2 的 u 一行),所以精度下降。在线结果(§4、§7.4)只部分支持这个估计:λ ≤ 2.4 不可区分;λ = 2.83 的 (A = 64, α = 0.25) 在 strat20 上 −8、在独立集上 +3,不能确认;稳定下降的是 λ 大而且斜率偏离 0.25 的配置——(16, 0.5)(λ = 4)−18 / −17,(32, 0.6774)(λ = 10.5)−18。也就是说 std 比值给出的是 λ 的量级,不是精确的边界。

**不存在精确补偿。** 命题:设块长在数据中至少取两个不同的值,则 (A′, α′) 与 (A, α) 对所有 query、所有 envelope 给出相同排序,当且仅当 A′ = A 且 α′ = α。证明:取长度 L₁ ≠ L₂ 的两个块,分数差分别为 (c₁ − c₂) + f(L₁)w₁ − f(L₂)w₂ 与 (c₁ − c₂) + f′(L₁)w₁ − f′(L₂)w₂,其中 w₁, w₂ ≥ 0、c₁ − c₂ 任意。要对所有取值同号,两个过原点的分界超平面必须重合,法向量 (1, f(L₁), −f(L₂)) 与 (1, f′(L₁), −f′(L₂)) 正比例;第一个分量都是 1,所以 f′(L₁) = f(L₁)、f′(L₂) = f(L₂)。于是 α′(ln A′ − ln L) = α(ln A − ln L) 在两个不同的 L 上成立,ln L 的系数相等(α′ = α),常数项相等(A′ = A)。∎ 唯一的例外是所有块等长(fixed-size chunking):因子是常数,任何 λ 相同的 (A′, α′) 都等价——**anchor 问题只在变长块下存在。**

**近似补偿。** 要求新旧因子在参考长度 L\* 处相等:(A′/L\*)^α′ = (16/L\*)^0.25,即
$$\alpha' = 0.25\cdot\frac{\ln(16/L^*)}{\ln(A'/L^*)}.$$

| L\* | A′ | ln(16/L\*) | ln(A′/L\*) | α′ | 说明 |
|---|---|---|---|---|---|
| 48(median) | 8 | −1.0986 | −1.7918 | 0.25 × 0.6131 = **0.1533** | 可行 |
| 48 | 32 | −1.0986 | −0.4055 | 0.25 × 2.7095 = **0.6774** | 可行 |
| 48 | 64 | −1.0986 | +0.2877 | −0.9547 | 无正解 |
| 48 | 48 | −1.0986 | 0 | 发散 | 无解 |
| 79(mean) | 8 | −1.5969 | −2.2900 | **0.1743** | 可行 |
| 79 | 32 | −1.5969 | −0.9037 | **0.4418** | 可行 |
| 79 | 64 | −1.5969 | −0.2106 | **1.896** | 可行但极陡 |
| 79 | 79 | −1.5969 | 0 | 发散 | 无解 |

A′ ≥ L\* 时无正解的原因很简单:目标值 (16/L\*)^0.25 = 0.76 < 1,而 A′ ≥ L\* 时 (A′/L\*)^α′ 对任何 α′ > 0 都 ≥ 1。这不是"A 必须小于块长"的规则,只是说明 median / mean 这类落在典型块长上的 A 无法用正的 α′ 复现默认的权重。更重要的是,补偿只能保住 L\* 一个点上的值,保不住斜率:

| L | 6 | 16 | 48 | 64 | 256 |
|---|---|---|---|---|---|
| (16/L)^0.25(默认) | 1.278 | 1.000 | 0.760 | 0.707 | 0.500 |
| (8/L)^0.1533 | 1.045 | 0.899 | 0.760 | 0.727 | 0.588 |
| (32/L)^0.6774 | 3.108 | 1.599 | 0.760 | 0.625 | 0.244 |

(32, 0.6774) 把 6 token 的块的 width term 放大 3.1 倍、把 256 token 的块压到 0.24 倍;(8, 0.1533) 几乎不随长度变化。它们的斜率都不等于 β,§2.3 的结论已经说明这两者都不会好;§3–§4 的实验证实了这一点。

### 2.6 长度因子的第二重作用:DOM 区与非 DOM 区的先验

region-aware chunker 让 DOM 块长 6–64、其他块长 64–256,两个区域的块长几乎不重叠。于是任何随 L 减小的因子同时也是一个偏向 DOM 块的先验:α = 0.25 时 DOM 块的 width term 系数在 1.28–0.71 之间,system / history 块在 0.71–0.50 之间;α 越大偏向越强。§3 的离线结果里 α 越大 needle 越高、sysCov 越低,就是这个机制。解释 α 的实验结果时要同时考虑两重作用:对 bound 长度偏差的校正(§2.3),以及区域先验(本节)。

### 2.7 与已有方法的关系

按块打分的方式,已有方法分成两类:

- **bound 型**:Quest [1] 用 min/max envelope 的 support function,page 固定 16 token,论文没有 page size 的消融,也没有讨论 bound 随 page 变松或按 page 长度归一化。ArkVale [2] 用 bounding volume(box + sphere)做 page digest,同样按 bound 排序,page 也是固定长度。AB-Sparse [3] 研究按 head 自适应的 block size,把"block 用 mean pooling 还是 min-max pooling 表示"列为与其正交的设计选择。
- **centroid 型**:MoBA [4] 的 gate 是 s_i = ⟨q, mean_pool(K[I_i])⟩(block 512 或 4096,top-3 / top-12);Tactic [5] 用变长 cluster(平均 32 token),按 q 与 cluster centroid 的点积排序;NSA 用可学习的压缩 key 代表每个 64 token 的 block;ClusterKV、Squeezed Attention 也按 centroid 打分。这类分数是 key 的平均而不是极值,天然不随块长增长,所以这些工作即使用变长 cluster(Tactic)也不需要长度归一化。

本文的 center term c = q·(M+m)/2 是 box 中心而不是 key 均值,但性质与 centroid 型相同:不随块长变化,与密度相关 +0.86。ctr-only 就是 centroid 型打分在 envelope 表示下的对应物;它在离线三项指标上全部最高,在线只差 −3。据我们检索,没有已有工作对 bound 型分数按块长做归一化;最接近的是 AB-Sparse 对 block size 敏感性的讨论。本文的贡献是把"为什么变长块下 bound 型分数需要归一化"(§2.2)、"归一化的斜率由什么决定"(§2.3–2.4)和"权重能放多大"(§2.5)三个问题在真实 KV 上量化了。

### 3.5 离线观察

1. **α 决定 needle 与 sysCov 之间的取舍。** 任一 A 下,α 从 0.125 升到 0.5,needle 单调上升(B1024 约 0.27 → 0.41),sysCov 单调下降(0.31 → 0.12)。机制是 §2.6 的区域先验:α 越大越偏向短的 DOM 块,system prompt 的长块被排除在 budget 之外。
2. **mass 在每个 A 下都在 α = 0.25 处最高**(B1024,A = 16:.242 / .259 / .225 / .200)。这与 §2.3–2.4 的 β = 0.245 一致。
3. **固定 α = 0.25 时,A 越小 mass 越高,而且单调。** B1024:A = 16 → 8 → 4 → 2 → 1 → 0.25 → 0 依次为 .259 / .263 / .266 / .268 / .269 / .272 / .277;sysCov 同向;needle 在 B1024 也同向(.280 → .296)。这与 §2.2 中"λ 越小、与密度的相关越高"的顺序完全一致。
4. **median / mean 作为 A 没有优势。** 它们在固定 α 下等于 λ = 2.6 / 3.0,mass .249 / .243 低于默认的 .259。
5. **补偿点没有优势。** 斜率大的配置(λ ≥ 4.6)needle 高但 sysCov 与 mass 大幅下降;斜率小的 (8, 0.1533) mass 与默认持平但 needle 更低。
6. **对数形式与幂律在 mass 上相同**(§2.3)。
7. **小 A 配合大 α**,如 (A = 1, α = 0.5),needle 比默认高 3 个百分点(B1024)和 8 个百分点(B2048),sysCov 与 mass 与默认持平。

### 3.6 离线代理的适用范围

之前的工作里离线代理有两次预测错了在线方向(`2026-09-01_codesign_report_mixmax_region_aware.zh.md` §6),原因都是跨"族"比较(不同的块几何或准入规则)。本节所有配置共享同一套块几何、准入规则和打分函数,只改 width term 的系数,离线排序的可信度更高。但 needle 与 mass 分别只衡量"参考元素是否在 budget 内"和"注意力覆盖",不等于模型最终动作的正确率,最终结论以 §4 的在线 agree 为准。§4.2 给出了离线三项指标与在线 agree 的秩相关。

在线 agree 与三个离线指标(B1024,§3)在这 15 个配置上的 Spearman 秩相关:mass **+0.67**,needle −0.15,sysCov +0.28。mass 是最好的离线预测量;needle 单独看是负相关(needle 最高的几个配置都是 sysCov 大幅下降的大 α 配置)。

观察:

1. **A 轴(α = 0.25)在 A ∈ [1, 32] 上不可区分。** ctr-only、1、4、8、16、32 的 agree 在 51–54 之间,与默认的 paired 差在 −3 到 0 之间,p ≥ 0.68。ctr-only 在离线三项指标上全部最高,在线却是 51,说明 width term 在线上既没有明显帮助也没有明显伤害——只要它的权重不大。
2. **A 变大在这个集合上有下降的迹象,但没有在独立集上重现。** A = 64(λ = 2.83)−8(p = 0.057),median(λ = 2.63)−6(p = 0.21),mean(λ = 2.98)−2;§7.4 中 A = 64 在 half2 上 +3。对"能否用 median / mean 做 A"的回答是:没有收益——它们等价于把 width term 的权重提高 30–50%,离线 mass 下降,在线没有任何一个集合上变好。
3. **α = 0.25 是 α 轴的最优点。** 0.125 → 45(−9;valid 从 100 降到 86、none 升到 39,模型更多地无法给出元素索引),0.375 → 51(−3),0.5 → 36(−18,p = 0.001)。与 §2.3–2.4 的 β = 0.245 和 §3.5 的 mass 峰一致。
4. **(A = 16, α = 0.5) 的大幅下降来自 λ = 4,不是斜率本身。** 同样斜率但 λ = 1 的 (A = 1, α = 0.5) 得到 52。width term 的绝对权重超过约 2.5 之后,长块的 bound 重新主导排序,system prompt 块被排除在 budget 之外(离线 sysCov 从 .217 降到 .126)。
5. **补偿点无效。** (8, 0.1533) → 48,(32, 0.6774) → 36。在参考长度处保住因子值、同时改变斜率,不能保住行为;后者 λ = 10.5,与 (16, 0.5) 一样差。这与 §2.5 的命题一致:换了 A 以后不存在能"补回来"的 α。

### 4.4 噪声下限与结果解读

1. **同一请求流下服务端完全可复现,不同请求流下有约 7% 的翻转。** 默认配置在阶段一的重复运行与第一次逐步相同;而在阶段二(同样的 132 步混在 190 步的请求流里,batch 组成不同)只有 123 / 132 步的 agree 标志相同,104 / 132 步的输出索引完全相同。也就是说,单次 132 步运行的跨流噪声约为 9 次翻转(W + L ≈ 9),方向对称、净差接近 0。解读标准:在 132 步上,|W − L| ≤ 3 是噪声,−6(median)在边缘,−8 / −9 / −18(A = 64、α = 0.125、α = 0.5)是真实下降。

## 5. 结论与建议

**16 是否可以替换?** 可以,但没有收益。α = 0.25 下,A 从 1 到 32(λ 从 1.0 到 2.4)在 369 个 step 上与 16 的差异都在 ±2 之内(p ≥ 0.87),A = 64 在 311 步上 −5(两个集合上 −8 / +3),连去掉 width term(ctr-only)也只差 −3。模型的动作对 width term 在这个权重范围内的变化不敏感。

**哪个实验效果最好?** 合并 369 步:A = 8 → 184,A = 4 → 183,A = 16 → 182,A = 1 → +1(311 步);B = 2048 上 A = 8 +2。这些差异比跨请求流的复现噪声(每 132 步约 9 次翻转)还小,没有一个可以说"更好"。half1 上 A = 4 的 +8 在独立的 half2 上没有重现,是噪声。

**理论依据(§2)。** (1) budget 下的选择是 knapsack,分数应当反映每 token 的 attention mass;Quest 的 bound 反映的是总 mass,对等长 page 两者排序一致,对变长块不一致。(2) bound 里只有 width term 随块长增长(随机片段上 w ≈ 17 + 47.6·ln L,在 8–256 上近似 L^0.245),center term 不增长;所以校正只作用在 w 上,斜率 α 取增长指数 β。(3) 增长来自 extreme value 与 RoPE 中频维度的旋转,是模型 key 几何的属性。(4) A 只是 width term 的权重 λ = A^α;std(c)/std(u) ≈ 1.3–2.5 给出 λ 的量级上限;在线上 α = 0.25 时 A 直到 64(λ = 2.8)仍在噪声内,真正有害的是 λ 大而且斜率偏离 0.25 的组合(§7.4)。

**"用 median / mean 做 A"为什么不行。** (1) 数学上,固定 α 时它们只是把 λ 提高到 2.6 / 3.0,没有引入任何自适应;(2) 它们落在典型块长上,近似补偿无正解;(3) 实验上离线 mass 下降(.249 / .243 vs .259),在线 strat20 上 −6 / −2(§7.4 表明 A 轴的在线差异都在噪声内)。

**建议。**
1. 默认值保持 `BSA2_WN_ANCHOR=16`、`BSA2_WN_ALPHA=0.25`(代码已把 A 做成可配置项,默认行为不变)。
2. 不要用 median、mean、64 或其他 ≥ 48 的 A;不要把 α 改离 0.25;不要按 §2.5 的公式"补偿"α。换模型时用 `measure_width.py` 重新测 β,取 α = β。
3. 若将来重新选默认值,A = 8 与 16 精度相同且离精度下降的一端更远;若想简化打分,ctr-only(无 width term、无 A 与 α)在线只差 −3、离线指标最高,并且与 MoBA / Tactic 的 centroid 型打分同属一类,值得在 B = 2048 与更大规模上再验证一次。
4. 同族打分超参数的离线筛选应看 mass(与在线 agree 秩相关 +0.67),不能只看 needle(−0.15)。

## 7. 补充验证:随机性、样本量、context 与模型(2026-09-10)

两个问题:(1) 离线实验对 random seed 敏感吗?(2) (A = 16, α = 0.25) 是只在这批 WebVoyager 数据上最优,还是对 sample size、网页、模型都稳定?

### 7.1 随机性从哪里来

离线 sweep(§3)本身不含随机数:输入是固定的 KV dump,query 取固定位置的 decode step(每 32 步一个加最后 4 个)。在线评测用 temperature = 0 的贪心解码,也没有随机数。真正带随机性的环节有四个,下面逐个测:

| 环节 | 随机性 | 测法 |
|---|---|---|
| 宽度增长指数 β 的随机片段抽样(§2.3) | `default_rng(seed)` 抽 150 个片段 | seed 0–5 各跑一次 |
| 离线 sweep 的 query 抽样 | 固定位置 | 改为每个 prompt 随机抽同样数量的 decode step,seed 1–5 |
| 离线 sweep 的 prompt 选择 | 23 个失败样本 | 对 prompt 做 bootstrap(1000 次重抽) |
| 在线评测的请求流顺序 | batch 组成随请求顺序变化 | 同一配置在原顺序、重复运行、half1 混合流、打乱顺序四条流上比较 |

### 7.7 结论(截至目前的数据)

1. **随机性:** 离线结论对片段 seed、query 抽样 seed、prompt 选择都不敏感;在线唯一的随机性是请求流顺序(约 7% 翻转),已用重复运行标定,所有结论都以此为噪声尺度。
2. **样本量与独立任务:** α = 0.25 的最优在 132 步与 179 步、两组互不重叠的任务上都重现,而且样本越大越清楚;A 在 1–64 内没有一致影响。
3. **网页 / context:** 按站点和 prompt 长度分层,没有任何一层的差别超过噪声;块长分布(长块几何)的扫描仍在排队。
4. **模型:** 是这个超参数唯一真正敏感的维度。Qwen3-VL-8B 上 α 的排序已经不同(0.5 ≥ 0.25),而且稀疏化本身的损失大得多;按理论,换模型时应重新测 β 并取 α = β,而不是沿用 0.25。这一点等 β 测量和剩余运行完成后定稿。
